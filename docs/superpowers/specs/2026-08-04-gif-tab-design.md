# GIF 탭 — 이미지→GIF + 영상→GIF 토글

날짜: 2026-08-04
대상: 웹앱(`index.html`) 전용.

## 목적

새 **GIF** 탭에서 토글(PDF 탭 패턴)로 두 기능을 제공한다:
- **이미지 → GIF**: 트레이에 넣은 이미지들이 순서대로 도는 애니메이션 GIF.
  순서 드래그 변경·전환 간격·최종 용량(크기·색상)·파일 이름 조절.
- **영상 → GIF**: 영상 업로드 → 크롭 + 타임라인 트림(시작/끝 핸들) → 그 구간만 GIF.

## 확정된 기술 결정

### ① GIF 인코더: 자체 구현 (GIF89a, 의존성 0)

앱 정체성(ZIP·PDF·EXIF 자체 구현)에 맞춰 인코더를 직접 만든다.
- 모든 프레임에서 픽셀 표본(≤32k) → **median-cut 글로벌 팔레트** (64/128/256색, 2^n 패딩)
- 팔레트 매핑: 15비트 양자화 키 캐시 + 최근접 탐색
- **LZW** 가변 코드폭(min 2~12bit), clear/EOI 코드, 255바이트 서브블록
- 구조: `GIF89a` 헤더 · LSD · GCT · **NETSCAPE2.0 무한 루프** · 프레임마다 GCE(delay
  1/100s, disposal 1) + Image Descriptor + LZW 데이터 · trailer
- 투명(PNG 알파)은 흰 배경 합성 (GIF 1비트 투명은 YAGNI)
- 프레임당 setTimeout yield + onProgress — UI 안 멎게
- 검증: Chrome `ImageDecoder`로 산출 GIF를 **실제 디코드** — 프레임 수·delay·픽셀 색 확인

### ② 영상 프레임 추출: seek 기반 배치 (실시간 아님 — 단계적 방안)

| 단계 | 방식 | 속도 | 상태 |
|---|---|---|---|
| 1 (이번) | `<video>` seek → canvas 캡처, fps 간격 | 프레임당 50~150ms (5초@10fps ≈ 수 초) + 진행률 | **구현** |
| 2 (향후) | `requestVideoFrameCallback` 재생 중 캡처 | ≈ 재생 속도 | 업그레이드 경로 |
| 3 (향후) | WebCodecs `VideoDecoder` | 디코드 속도(최속) | 업그레이드 경로 |

seek 방식은 프레임 시각이 정확하고 모든 최신 브라우저에서 동작한다. `<video>`가
재생할 수 있는 포맷(MP4/H.264, WebM 등)을 그대로 받는다.

## UI

```
탭: GIF (PDF 옆)
#gifModeSeg 토글: 🖼️ 이미지 → GIF (기본) | 🎬 영상 → GIF

[이미지 → GIF]  #img2gifBody
  드롭존(여러 장) → #gifTray (pdf-pages 스타일: 썸네일 + ⠿ 드래그 순서 + ✕)
  전환 간격 슬라이더 0.1~2.0s (기본 0.5) · 크기 240/360/480/640 (기본 480)
  색상 64/128/256 (기본 256) · 파일 이름 입력
  [GIF 만들기] → 진행률 → 결과(움직이는 미리보기·용량·치수) + 다운로드/공유/비우기

[영상 → GIF]  #v2gBody
  드롭존(video/*) → <video> 미리보기
  크롭: 미리보기 위 드래그로 사각형(이동 가능) + [크롭 초기화] — 분할 가이드라인 패턴
  트림: 필름스트립(썸네일 ~10장) + 시작/끝 핸들 드래그 + 시간 라벨 + 구간 하이라이트
  fps 5/10/15 (기본 10) · 크기·색상·이름 (이미지 모드와 동일 칩)
  [GIF 만들기] → 프레임 추출 진행률 → 인코딩 진행률 → 결과
```

- 옵션이 결과와 달라지면 "설정이 바뀌었어요 — 다시 만들어 주세요" 안내(자동 재변환은
  인코딩이 수 초라 하지 않음).
- 프레임 상한 300장(메모리 보호) — 초과 구간은 경고 후 앞부분만.

## 편의 기능 (다른 탭 관례를 따름)

- `routeFiles` gif 분기: 이미지 → 트레이(모드 자동 전환), 영상 → 영상 모드 자동 전환
- Ctrl+V 이미지 붙여넣기 → 트레이
- 결과 클릭 → 라이트박스 / `bindShare` 공유 / 대기열·결과 비우기
- seq 가드(추출·인코딩 중 파일 교체·비우기 안전), busy 중 버튼 비활성
- 탭 아이콘·tabs 메타·README 갱신, sw.js CACHE 버전 상승

## 검증 (headless 하네스)

1. 인코더 왕복: 3색 프레임 GIF → `ImageDecoder` 디코드 → 프레임 3·delay 50(=500ms)·
   각 프레임 대표색 일치·무한 루프 바이트 존재
2. 트레이 순서 드래그 → 재인코딩 시 첫 프레임 색 변경
3. 간격·크기·색상 옵션 반영 (delay 값·출력 치수·팔레트 크기)
4. 영상 E2E: MediaRecorder로 합성 WebM(색 전환 애니메이션) 생성 → 업로드 → 트림
   구간만 → 프레임 수·색 순서·크롭 치수 확인 (헤드리스에 MP4 인코더가 없어 WebM으로
   대체 — `<video>` 경로는 동일)
5. 라우팅·토글·기존 탭 회귀 스모크

## 부록 (2026-08-04, 사용자 피드백 반영)

- **트림 미세 조정(줌)**: 좁게 잡은 구간을 "🔍 구간 확대"로 펼친다 — 뷰 윈도를 선택
  구간 ±30%(최소 0.3s)로 줄이고 필름스트립을 그 범위로 다시 그린다. 핸들·음영·클릭
  전부 뷰 기준 매핑, 최소 간격도 뷰 폭의 2%로 촘촘해진다. "↩ 전체 보기"로 복귀.
- **미리보기 (양쪽 모드)**: 이미지 모드는 트레이를 지금 순서·간격대로 캔버스에 순환
  재생(인코딩 없이, 간격은 라이브 반영), 영상 모드는 선택 구간을 반복 재생(크롭
  프레임 겹침 표시). 만들기·핸들 드래그·비우기가 자동으로 미리보기를 멈춘다.
  미리보기·만들기·필름스트립 생성은 서로 seek 경쟁하지 않도록 상호 중단·재개한다.
- **크롭 재설계**: "사각형 그리기" 대신 **전체 프레임에서 시작해 테두리·모서리
  핸들(8개)을 끌어 안쪽으로 좁혀 나가는** 방식. 안쪽 드래그 = 이동, 호버 시 리사이즈
  커서, 최소 24px, 초기화 = 전체 프레임.
